## 一、访问方式

### 电脑端访问

**最简单：直接打开浏览器**

1. 打开 Chrome 或 Edge 浏览器
2. 输入网址：https://g-aliang.github.io/cook-guide/
3. 即可使用

**本地开发模式（需要 Node.js）**

```bash
cd D:\code\cook
npm install      # 首次需要
npm run dev      # 启动开发服务器
# 浏览器访问 http://localhost:5173
```

### 手机端访问

**方式一：同 WiFi 下访问（推荐）**

1. 确保手机和电脑在同一 WiFi
2. 手机浏览器打开：http://192.168.1.7:5173（开发模式）
3. 或 http://192.168.1.7:4173（预览模式）

**方式二：公网访问（已部署）**

1. 手机浏览器打开：https://g-aliang.github.io/cook-guide/
2. 建议添加到主屏幕（PWA 安装）
   - Android：浏览器菜单 → 添加到主屏幕
   - 之后可以像 App 一样从桌面启动，支持离线

## 二、功能说明

### 首页

首页展示学习进度概览（已做 X 道、想做 Y 道）和 6 个快捷入口：

| 入口 | 说明 |
|------|------|
| 食材库 | 浏览所有食材，按分类筛选 |
| 菜品库 | 浏览所有菜品，按分类/难度/标签筛选 |
| 选菜匹配 | 勾选食材，一键匹配可做的菜 |
| 收藏 | 收藏的菜品列表 |
| 浏览记录 | 最近看过的菜品和食材 |
| 设置 | 版本管理、数据导出/导入/重置 |

### 食材库

**浏览：**
- 点击首页"食材库"或底部导航"食材"
- 顶部分类标签栏切换分类（蔬菜、肉禽、海鲜水产等 9 大类）
- 搜索框输入食材名称搜索

**查看详情：**
- 点击食材卡片进入详情页
- 详情页包含 9 大信息模块：介绍、品种、没有它可以用…、购买/挑选、储存、处理、相关菜品、营养成分、个人备注
- 第 3 个模块**「没有它可以用…」**是替代食材：缺货时按建议换料，点一下直接跳到那个食材（番茄这类找不到真替代的食材不显示此模块）
- 调味类食材的第 6 个模块显示为**「使用时机与用量」**，说明每味调料**什么时候放、放多少**
- 相关菜品可直接点击跳转

**添加食材：**
- 食材库页面点击"+ 新增食材"
- 填写 9 大模块所有信息
- 支持上传食材图片（≤500KB）

**调味料使用时机速查：**

| 类型 | 什么时候放 | 代表 |
|------|-----------|------|
| 提鲜、怕久煮 | 出锅前 / 最后放 | 生抽、味极鲜、蚝油、味精、鸡精、香油、花椒油 |
| 需要时间出味 | 早放（冷油炒香） | 豆瓣酱、黄豆酱、甜面酱、花椒粒、八角、桂皮 |
| 只负责上色 | 中途放（加水后） | 老抽、冰糖（炒糖色） |
| 看目的 | 要酸味早放 / 要醋香出锅前沿锅边淋 | 陈醋 |

几个容易踩的坑：
- 蚝油、味精、香油都怕高温久煮，一律最后放
- 豆瓣酱、花椒粒、八角桂皮需要时间出味，一律早放
- 醋看目的：要酸味早放（酸味会柔和），要醋香晚放（锅边醋）
- 糖在红烧菜里早放不只是甜，还能和氨基酸反应产生鲜味（美拉德反应）

### 菜品库

**浏览：**
- 点击首页"菜品库"或底部导航"菜品"
- 顶部标签栏：主分类（凉菜/热炒/汤羹/主食/甜点）+ 难度（入门/进阶/挑战）
- 多维度标签筛选：烹饪方式、荤素、菜系、时段
- **搜索框支持按食材名搜菜**：输入"五花肉"，直接列出用得上它的菜（红烧肉、回锅肉…），比走"选菜匹配"更轻
- 卡片上会标注命中的食材（如「🧺 含 五花肉」），一眼看出为什么被搜出来

**查看详情：**
- 点击菜品卡片进入详情页
- 包含：基本信息、分类标签、食材清单、制作步骤、营养信息、个人备注、相关食材
- 食材可点击跳转到食材详情；「或」式食材显示为**主料 + 备选**，例如"土鸡 或 鸡腿"——买不到土鸡用鸡腿也行
- 步骤时间徽标**点一下就开始倒计时**，结束时响铃 + 手机震动
- 可收藏、标记"已做过"/"想做"
- 基本信息卡片下方有**「🍳 厨房模式 · 大字一步一屏」**入口

**添加菜品：**
- 菜品库页面点击"+ 新增菜品"
- 填写基本信息、选择分类标签、添加食材清单、编写步骤
- 支持上传菜品图片和视频链接

### 厨房模式与步骤倒计时

**进入厨房模式**：菜品详情页 → 点「🍳 厨房模式 · 大字一步一屏」。

| 特性 | 使用方式 |
|------|----------|
| 大字 | 步骤正文自动放大到手机上也看得清，站在灶台前不用凑近 |
| 一步一屏 | 一次只显示一个步骤，顶部显示"3 / 8"进度 |
| 翻页 | 手机**左右滑动**；电脑按 **← / →**；退出按 **Esc** 或右上角 ✕ |
| 屏幕常亮 | 进入后左上角显示"● 屏幕常亮"，说明正在保持亮屏（安卓 Chrome 支持；iOS 不支持，只会不常亮，其他功能照常） |
| 计时 | 步骤上的"⏱ 3分钟"点一下开始倒计时，计时条浮在底部按钮上方，可暂停/继续/关闭 |
| 自动退出 | 最后一步点"完成 ✓"、或切换菜品时自动退出，页面滚动状态恢复 |

**步骤倒计时说明：**

- 只有带时间的步骤才能点；点开后在屏幕底部出现计时条，显示"第 3 步 · 3分钟"和剩余时间
- 倒计时按真实时间计算，切到别的页面再回来不会走慢
- 归零时响三声提示音并震动（手机），计时条变成可"再来一次"
- 首次点击需要你的操作（浏览器要求）才能出声，点计时按钮本身就是这个操作

## 三、代码更新流程

### 更新代码后需要做什么

1. 修改代码文件（src/ 目录下）
2. 本地测试：`npm run dev` → 浏览器验证功能
3. 构建生产版本：`npm run build`
4. 推送到 GitHub
5. GitHub Pages 自动更新

### 详细步骤

**步骤 1：修改代码**

在 `src/` 目录下修改或新增文件。

**步骤 2：本地测试**

```bash
npm run dev
```

浏览器打开 http://localhost:5173 验证功能是否正常。

**步骤 3：构建生产版本**

```bash
npm run build
```

会在 `dist/` 目录生成静态文件。

**步骤 4：推送到 GitHub**

```bash
# 提交代码
git add -A
git commit -m "更新说明"
git push

# 推送更新后的 dist 到 gh-pages 分支
cd dist
git init
git add -A
git commit -m "更新: 说明"
git push --force https://github.com/G-aliang/cook-guide.git HEAD:gh-pages
cd ..
```

**步骤 5：验证**

等待 1-2 分钟，访问 https://g-aliang.github.io/cook-guide/ 确认更新已生效。

> 💡 **注意：** 代码更新通过 GitHub Actions 自动部署。dist 目录的更新需要手动推送到 gh-pages 分支。

## 四、数据更新

### 初始数据与自动同步

应用首次打开时自动导入基础数据（食材、菜品），数据从 `public/import-data.json` 加载。

**数据版本自动同步机制：**

数据文件带 `dataVersion` 版本号（格式 `YYYYMMDDNN`：日期 + 当日序号，例如 `2026110401`），应用每次启动时会自动比对：

| 情况 | 行为 |
|------|------|
| 首次访问（数据库为空） | 全量导入基础数据 |
| 版本变化（远端 ≠ 本地） | **自动更新基础数据** |
| 版本相同 | 跳过 |

**关键：只更新基础数据（食材/菜品/做法），个人数据完整保留。**

| 数据 | 更新时 |
|------|--------|
| 食材、菜品、菜品-食材关联 | ✅ 自动刷新为最新 |
| 个人备注、收藏、浏览记录、学习进度、上传图片 | 🔒 完整保留 |

> 因此：**发布新数据后，你只需刷新页面（必要时 Ctrl+F5），所有设备都会自动拿到新版，无需手动清缓存。** 若某道菜被新版数据删除，它上面残留的备注/收藏会被自动清理。

### 手动更新数据

**方式一：通过应用内编辑**

直接在应用中新增/编辑/删除食材和菜品，数据自动保存到浏览器 IndexedDB。

**方式二：更新初始数据文件**

1. 编辑/生成数据（走 `ai-gen` 流程，或改 `generate-data.js`）
2. 重新合并/生成（脚本会自动同步到 `data/` 和 `public/`）：
   ```bash
   node merge-dishes.js        # 合并 AI 生成的数据（推荐）
   # node generate-data.js     # 从零重建（慎用，会覆盖）
   ```
3. 重新构建并推送（`npm run build` → 推 gh-pages）
4. 各设备刷新页面即自动同步新版

**方式三：通过设置页导入/导出**

- **导出：** 设置页 → 导出数据 → 下载 JSON 备份文件
- **导入：** 设置页 → 导入数据 → 选择 JSON 文件 → 选择覆盖或合并

### 数据同步（跨设备）

各设备数据独立存储在浏览器本地：

- **基础数据**（食材/菜品）：通过上面的版本机制**自动同步**
- **个人数据**（备注/收藏/历史/进度）：需**手动同步**
  1. 在设备 A 上：设置 → 导出数据 → 下载 JSON
  2. 将 JSON 文件传输到设备 B
  3. 在设备 B 上：设置 → 导入数据 → 选择 JSON → 覆盖或合并

## 五、构建方式：自动 vs 手动

### 代码部分：自动构建

GitHub Actions 工作流会在代码推送到 main 分支时自动执行：
1. 安装依赖（npm ci）
2. 构建项目（npm run build）
3. 准备部署

工作流文件：`.github/workflows/deploy.yml`

### dist 部分：手动推送

当前部署方式是手动推送 dist 到 gh-pages 分支。每次更新代码后需要：

```bash
npm run build
cd dist
git init && git add -A && git commit -m "更新说明"
git push --force https://github.com/G-aliang/cook-guide.git HEAD:gh-pages
cd ..
```

> 💡 后续可以优化为 GitHub Actions 自动推送 dist 到 gh-pages 分支，实现全自动部署。

## 六、常见问题

### Q: 手机打不开网站？

- 检查手机和电脑是否在同一 WiFi
- 如果是公网访问，确认网络可以访问 github.io
- 尝试使用 https://g-aliang.github.io/cook-guide/ 而非 IP 地址

### Q: 数据会丢失吗？

- 数据存储在浏览器 IndexedDB 中
- 清除浏览器数据会导致数据丢失
- 建议定期在设置页导出备份
- 导入新数据时可选择"覆盖"或"合并"

### Q: 如何添加自己的菜谱？

- 菜品库页面点击"+ 新增菜品"
- 填写所有信息后保存
- 数据自动保存到本地浏览器

### Q: 怎么知道有新版本？

- 新版本下载完成后，页面底部会弹出「有新版本，点击刷新」
- 点「刷新」立即生效；点「以后」稍后再更新，当前使用不受影响
- 刷新**不会覆盖**你的备注、收藏、浏览记录和学习进度
- 长时间不关页面也会自动检查（每小时一次，切回页面时也会查）

### Q: 更新代码后网站没变化？

- 先看有没有底部"有新版本"提示，有就直接点刷新
- 没有提示的话：检查是否推送了 gh-pages 分支，等 1-2 分钟让 Pages 重新发布
- 老版本（未升级到此版）需要手动强刷一次（Ctrl+F5），之后就都有提示了

### Q: 厨房模式屏幕常亮没用？

- 屏幕常亮依赖浏览器的 Wake Lock 能力，需要 **HTTPS + Chromium 内核**（安卓 Chrome/Edge）
- iOS Safari 不支持，表现为不常亮，其他功能正常
- 手机系统开了"省电模式"或把浏览器切到后台，常亮会被系统取消；切回页面会自动重新申请

### Q: 如何安装为手机 App？

- Android Chrome：打开网站 → 菜单 → 添加到主屏幕
- 之后可以从桌面直接启动，支持离线访问
