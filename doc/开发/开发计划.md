# 家常菜入门指南 — 开发计划

> 版本：v1.0  
> 日期：2026-10-31  
> 状态：计划制定完成，待开发  
> 说明：本文档为详细开发计划，包含各模块开发任务和验证标准。每步必须通过验证才能进入下一阶段。

---

## 一、总体计划

### 1.1 开发阶段总览

| Phase | 阶段名称 | 预估工期 | 核心产出 |
|-------|----------|----------|----------|
| Phase 1 | 基础设施搭建 | 1-2 天 | 项目框架、路由、数据层、CSS 框架 |
| Phase 2 | 食材模块 | 2-3 天 | 食材列表、详情（8模块）、增删改 |
| Phase 3 | 菜品模块 | 3-4 天 | 菜品列表、多维度筛选、详情、增删改 |
| Phase 4 | 双向关联 + 选菜匹配 | 2-3 天 | 关联导航、匹配算法、匹配结果 |
| Phase 5 | 个人中心 | 2-3 天 | 收藏、浏览记录、学习进度、设置 |
| Phase 6 | 图片与视频 | 2 天 | 图片上传、展示、视频链接 |
| Phase 7 | 初始数据填充 | 5-7 天 | 100+ 食材、500+ 菜品数据 |
| Phase 8 | 部署上线 | 1-2 天 | GitHub Pages、PWA 安装 |

**总计预估：18-24 天**

### 1.2 开发原则

1. **逐阶段验证**：每个 Phase 完成后必须通过验证标准才能进入下一阶段
2. **前端与数据层同步**：前端开发与数据结构开发同步进行，不积压
3. **每阶段可运行**：每阶段产出可运行的功能，不留半成品
4. **数据收集并行**：Phase 7 数据收集可与 Phase 2-6 开发并行进行
5. **先功能后优化**：先实现核心功能，再做视觉打磨和性能优化

### 1.3 开发顺序与依赖关系

```
Phase 1 (基础设施)
    ↓
Phase 2 (食材模块) ──────────┐
    ↓                        │
Phase 3 (菜品模块) ─────────┤
    ↓                        │
Phase 4 (双向关联 + 选菜匹配) │
    ↓                        │
Phase 5 (个人中心)           │
    ↓                        │
Phase 6 (图片与视频)         │
    ↓                        │
Phase 7 (初始数据填充) ←── 可与 Phase 2-6 并行
    ↓
Phase 8 (部署上线)
```

**关键依赖：**
- Phase 2 和 Phase 3 必须在 Phase 4 之前完成（双向关联依赖两个模块）
- Phase 7 数据收集应在 Phase 8 之前完成（部署需要完整数据）
- Phase 1 是所有模块的基础，必须最先完成

## 二、Phase 1：基础设施搭建

### 开发任务

**1.1 项目初始化**
- 创建 Vue 3 + Vite 项目
- 安装依赖：Vue Router、Pinia、Dexie.js、vite-plugin-pwa
- 配置 `browserslist`（Chrome 80+ / Edge 80+ / Android Chrome）

**1.2 路由搭建**
- 配置 Hash 路由（`createWebHashHistory`）
- 定义所有路由：

| 路由 | 组件 |
|------|------|
| `/` | Home |
| `/ingredients` | IngredientList |
| `/ingredients/:id` | IngredientDetail |
| `/dishes` | DishList |
| `/dishes/:id` | DishDetail |
| `/match` | Match |
| `/match-results` | MatchResults |
| `/profile` | Profile |
| `/favorites` | Favorites |
| `/history` | History |
| `/progress` | LearningProgress |
| `/settings` | Settings |

**1.3 数据层搭建**
- `database.js`：定义 8 张表
- `ingredientModel.js`：食材数据模型（getAll/getById/getByCategory/search/insert/update/remove/getRelatedDishes）
- `dishModel.js`：菜品数据模型（getAll/getById/getByCategory/getByDifficulty/search/insert/update/remove(级联)/getRelatedIngredients/matchByIngredients）
- `noteModel.js`：备注数据模型（getByRef/insert/update/remove）
- `browsingHistoryModel.js`：浏览记录模型（record/getRecent/remove/clear）

**1.4 状态管理搭建**
- Pinia store：useIngredientStore / useDishStore / useFavoriteStore / useHistoryStore / useProgressStore / useNoteStore

**1.5 基础 CSS 框架**
- CSS 变量：色彩体系（橙/绿/红 + 中性灰）、字体规范、间距体系、圆角阴影
- 全局样式重置
- 通用组件样式：卡片、按钮、标签、输入框

**1.6 组件框架**
- `NavBar.vue`：顶部导航栏
- `BottomNav.vue`：底部导航栏（4 项：首页/食材/菜品/我的）
- 通用组件骨架

### 验证标准

| 验证项 | 标准 | 测试方法 |
|--------|------|----------|
| 项目运行 | `npm run dev` 启动无报错 | 终端输出 |
| 路由生效 | 所有路由可访问，Hash 模式正常 | 浏览器逐路由访问 |
| 数据库初始化 | `db.open()` 成功，8 张表创建 | 控制台输出 |
| 数据模型 | 所有 Model 方法可调用，返回正确 | 单元测试 |
| CSS 变量 | 色彩/字体/间距变量正确定义 | 代码审查 |
| 底部导航 | 4 项图标+文字，当前页高亮 | 原型图对照 |
| 顶部导航 | 搜索框+功能入口正常 | 原型图对照 |

**边界值测试：**
- 空数据库启动 → 正常初始化，不报错
- 数据库已存在数据 → 正常加载，不重复初始化
- 路由刷新（F5）→ Hash 路由不 404

**安全考量：**
- browserslist 配置正确，不引入不兼容语法
- 无 Cookie/Session，无隐私泄露风险

**完成标志：** `npm run dev` 启动后能看到空壳页面，导航栏可切换，数据库可读写。

**异常值测试：**
- 图片 > 500KB → 拒绝上传，提示"图片过大"
- 图片格式不支持 → 拒绝上传，提示"仅支持 JPG/PNG/WebP"
- 备注 > 500 字 → 限制输入，提示"超出字数限制"
- 营养成分数值为空 → 保存时允许，展示时显示"—"
- 品种/储存/处理数组为空 → 保存时允许，展示时显示"暂无"

**安全考量：**
- 输入框 XSS 防护（禁用 v-html，使用 v-text）
- 删除操作二次确认
- 图片 base64 数据不溢出（500KB 限制）

**完成标志：** 食材列表可浏览、搜索、筛选，食材详情页 8 大模块完整展示，增删改数据持久化。

| 导入恢复图片 | 导入后图片正确恢复 | 功能测试 |

**边界值测试：**
- 图片 > 500KB → 拒绝上传，提示"图片过大"
- 图片格式不支持 → 拒绝上传，提示"仅支持 JPG/PNG/WebP"
- 无图片的食材/菜品 → 显示 emoji 占位
- 视频链接为空 → 不显示视频区域
- 视频链接格式错误 → 保存允许，展示时不渲染播放器
- 备注图片 > 3 张 → 限制第 4 张

**异常值测试：**
- 图片上传过程中网络中断 → 提示"上传失败"
- 多张图片同时上传 → 逐张处理，不阻塞
- 图片 base64 数据异常 → 显示错误提示

**性能考量：**
- 图片延迟加载（不阻塞页面渲染）
- 列表页不加载图片，详情页按需加载
- 大图片自动压缩（可选优化）

**安全考量：**
- 图片 base64 数据不执行脚本
- 视频链接仅允许 http/https
- 图片上传大小限制防止存储攻击

**完成标志：** 图片可上传/展示/删除，视频链接可展示，导出导入包含图片数据。
